# STA site restoration – progress checkpoint

**Objective:** make the Elementor test site (`https://stastudent.no/reliant/`, WP Staging, login required) reproduce the reference `https://stastudentphp.vercel.app/` while staying natively editable in Elementor (free 4.3.5 + HappyAddons; **no Elementor Pro** → no Theme Builder / per-element custom CSS).

## How it works now
- The reference is a static export of this theme's own PHP templates (`sta-wordpress/public_html`), i.e. the intended design.
- Pages with **Page Layout = Elementor Full Width** (`elementor_header_footer`) get body class `sta-native-layout`; `page.php` prints `the_content()` with no wrapper, so Elementor controls the whole content area. Header/footer stay theme PHP (shared, unchanged).
- Legacy `!important` hacks in `main.css` (white headings, white button text, first-child resets, page-id hacks) are scoped to `body:not(.sta-native-layout)`; homepage keeps its white-heading rule via `.elementor-11503`.
- Page content was generated by `sta-wordpress/tools/elementor-converter/elementor_converter.js`: reads the reference DOM + computed styles at 1280 / 900 / 390 px and emits native containers (flex/grid), Heading, Text Editor, Button, Image, Icon, Icon List widgets with responsive values. Imported and **saved through the Elementor editor** (`staging_helpers.js` → `STAImport`), so revisions exist.
- Transfer reference → staging via `window.name`; theme ZIPs uploaded with Claude in Chrome (built-in browser can't attach files). Build ZIP with `python sta-wordpress/tools/build_theme_zip.py` (old JS zip writer made archives WP rejects).
- Media URLs point at staging uploads (`/reliant/wp-content/uploads/...`; all 41 verified 200). WP Staging rewrites URLs on push.

## Rollback
- Git tag `pre-native-restoration` (both repos); old ZIP `scratch/sta-theme-v1.2.9-backup.zip`.
- Per page: Elementor revisions, plus previous element JSON in staging-origin `localStorage['sta_backup_<id>']`.
